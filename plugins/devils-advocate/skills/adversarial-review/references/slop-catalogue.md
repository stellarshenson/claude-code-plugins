# Slop catalogue

The tells, worked examples and measured evidence behind each axis of the `slop-hunter` adversary. The persona carries the headline per axis; this file carries what a reviewer needs to recognise the class in a diff and to say why it matters. Read it in Mode 2 (tools on); in Mode 1 the persona's headlines are the whole standard.

Every source below was fetched and read on 2026-09-03: the title links the page, the quoted sentence is what the page says. Argue from the quote; a reviewer that paraphrases a number invents one. Five figures the persona leans on were re-verified against the source text a second time: the GitClear 8-fold sentence, the Hora & Robbes mock rates, the MUTGEN coverage-versus-mutation pair, the SWE-ABS rejection rate and the Tang et al. episode shares.

## Where machine-generated bloat concentrates

Ranked by the strength of the measurement, so the sweep starts where the evidence points.

1. **Duplication over reuse** - [GitClear 2025](https://gitclear-public.s3.us-west-2.amazonaws.com/GitClear-AI-Copilot-Code-Quality-2025.pdf), 211 million changed lines, 2020-2024: "we recorded an 8-fold increase in the frequency of code blocks with 5+ duplicated lines during 2024" and "2024 marked the first year GitClear has ever measured where the number of 'Copy/Pasted' lines exceeded the count of 'Moved' lines". [GitClear 2026](https://www.gitclear.com/the_ai_code_quality_maintainability_gap), 623 million changes: copy/paste 15.7% against moved code 3.8% in H1 2026. [Faros AI 2026](https://www.faros.ai/blog/ai-acceleration-whiplash-takeaways), 22,000 developers: "Code churn...has increased 861% under high AI adoption"
2. **Tests** - [Hora & Robbes, MSR 2026](https://arxiv.org/abs/2602.00409), 1.2 million commits: "36% of commits made by coding agents add mocks to tests, compared with 26% by non-agents". [MUTGEN](https://arxiv.org/abs/2506.02954): "some test suites achieve 100% coverage but only 4% mutation score". [Meta TestGen-LLM](https://arxiv.org/abs/2402.09171): "75% of TestGen-LLM's test cases built correctly, 57% passed reliably, and 25% increased coverage"
3. **Fake passes** - [SWE-ABS](https://arxiv.org/abs/2603.00520) strengthens SWE-bench Verified tests and "rejects 19.71% of previously passing patches". [Claude Opus 4.5 system card](https://www-cdn.anthropic.com/bf10f64990cfda0ba858290be7b8cc6317685f47.pdf) table 6.10.1.A: hack rate on impossible tasks 55% unprompted, 35% with the anti-hack prompt. [METR, June 2025](https://metr.org/blog/2025-06-05-recent-reward-hacking/): reward hacking in 30.4% of RE-Bench runs
4. **Scope** - [RECAP](https://arxiv.org/abs/2608.13292): "even successful patches are consistently larger and more complex than developer patches", median 121.78% more total changes and 43.99% higher cyclomatic complexity. [Tang et al.](https://arxiv.org/abs/2605.29442), 16,118 validated episodes, Table 3: Developer Constraint Violation 38.33%, Self-Initiated Overreach 10.20%
5. **Defensive guards** - vendor-documented, not measured: Anthropic's [prompting guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) names "a tendency to overengineer by creating extra files, adding unnecessary abstractions, or building in flexibility that wasn't requested"
6. **False verification claims** - Tang et al. Table 3: Inaccurate Self-Reporting 22.58% of episodes. [METR Frontier Risk Report](https://metr.org/blog/2026-05-19-frontier-risk-report/): grading agents is slower than grading humans "because of how often models overclaim and describe what they did in highly misleading ways"
7. **Hallucinated packages** - [Spracklen et al., USENIX Security 2025](https://arxiv.org/abs/2406.10279), 576,000 samples: package hallucination "at least 5.2%" for commercial models and "21.7%" for open-source, 205,474 unique phantom names

Two assumptions the measurements contradict:

- **Generated code under-comments.** [Automatic Detection of LLM-Generated Code](https://arxiv.org/html/2409.01382v2): LLM functions carry 1.22 comment lines against 9.57 for humans. [Ji et al., JSS 2026](https://arxiv.org/abs/2607.01867): LLM-attributed comments show "a relatively low proportion of grammatically correct sentences". Comment findings are about restatement and annotations on untouched lines, not volume
- **Verbosity is in the change, not the line.** [Human-Written vs. AI-Generated Code](https://arxiv.org/abs/2508.21634), 500k samples: "AI-generated code is generally simpler and more repetitive, yet more prone to unused constructs and hardcoded debugging". [A Large-Scale Empirical Study of AI-Generated Code in Real-World Repositories](https://arxiv.org/abs/2603.27130): "real-world AI-Human differences on code-level metrics are rather small"; the commit-level signals (size, stability) carry more

## Axis 1 - dead code

- **Tells** - a function whose only reference is its definition; an import the linter greys out; a parameter every caller passes the same value or none; `if False:` and code after `return`; a flag read once and always one value; `print(` / `console.log(` with a debugging payload; a script under `scripts/` or `tmp/` with one run in its history, committed beside the change
- **Example** - `def _legacy_parse(...)` kept "in case", zero callers; `DEBUG_DUMP = False` guarding a block nothing flips
- **Evidence** - [Human-Written vs. AI-Generated Code](https://arxiv.org/abs/2508.21634): AI code is "more prone to unused constructs and hardcoded debugging". Anthropic's [prompting guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) sample prompt: "Do not create helper scripts or workarounds"

## Axis 2 - duplication and re-implementation

- **Tells** - five or more consecutive lines that already exist elsewhere in the tree; a second `slugify`, `retry`, `parse_date` or `load_config` next to the existing one; the same regex, schema, error message or constant declared twice; the same setup block at the top of every test function instead of a fixture; a diff that is all additions where a move or a rename was the change
- **Example** - `utils/text.py::normalise()` added in a session that read `core/normalise.py` two hours earlier; six test functions each opening with the same eight-line client construction
- **Cause** - the agent wrote instead of searched. [Lost in the Middle](https://arxiv.org/abs/2307.03172): "performance can degrade significantly when changing the position of relevant information". [Chroma, Context Rot](https://www.trychroma.com/research/context-rot), 18 models: "model performance varies significantly as input length changes, even on simple tasks". [Anthropic, context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): "As the number of tokens in the context window increases, the model's ability to accurately recall information from that context decreases". [Mehtiyev & Assunção](https://arxiv.org/abs/2604.02547), 9,374 trajectories: "agents that gather context before editing and invest in validation succeed more often"
- **Evidence** - GitClear 2025 and 2026 and Faros 2026 as quoted above. [Ji et al.](https://arxiv.org/abs/2607.01867): LLM-attributed code "demonstrated substantial intra-repository code clones" and "appeared frequently in test cases". [Claude Code best practices](https://code.claude.com/docs/en/best-practices) recommends asking first "whether we have any existing OAuth utilities I should reuse"
- **Delete-test** - grep the copy's most distinctive line; a hit outside the copy is the original. Two copies that have drifted are a design finding, not a delete

## Axis 3 - speculative and single-use abstraction

- **Tells** - a factory with one product; an interface with one implementation; an adapter wrapping one call; a `BaseX` with one subclass; a plugin registry with one plugin; a `Config` field only ever set to its default; a strategy selected by a flag no caller sets; a "generic" helper whose only caller passes literals
- **Example** - `class StorageBackend(ABC)` plus `class LocalStorage(StorageBackend)` and no second backend on any roadmap; `def render(fmt="svg")` where every caller passes `svg`
- **Evidence** - Anthropic's prompting guide sample prompt: "Don't create helpers, utilities, or abstractions for one-time operations. Don't design for hypothetical future requirements. The right amount of complexity is the minimum needed for the current task". The shallow-module test is Ousterhout's (A Philosophy of Software Design); the wrong-abstraction argument is Metz's (The Wrong Abstraction): duplication would have been cheaper
- **Delete-test** - "what requirement would have to change for a second caller to appear?"; if none is close, inline. A one-setting knob collapses to a named constant in the configuration plane, never to an inline literal

## Axis 4 - defensive slop

- **Tells** - `try: ... except Exception: pass` or log-and-continue around an internal call; `if x is None:` on a value the type annotation or the framework guarantees; a validator on an internal caller; a fallback branch for a failure no input produces; a retry loop around a local function; a size cap, timeout or limit nobody measured a need for; a guard whose commit message names a reviewer round
- **Example** - `if not isinstance(items, list): items = []` inside a function whose one caller builds the list two lines earlier; `except KeyError: return DEFAULT` on a dict the same module populates
- **Boundary exemption** - a check at a boundary (user input, network, file, subprocess, untrusted data) with a named input stays and is never flagged. Anthropic's rule: "Only validate at system boundaries"
- **Evidence** - Anthropic's prompting guide: "Don't add error handling, fallbacks, or validation for scenarios that can't happen. Trust internal code and framework guarantees. Only validate at system boundaries"; the same rules ship in the Claude Code system prompt ([third-party capture, 9 Dec 2025](https://blog.thepete.net/claude-code-system-prompt/)), so a guard of this class in a diff means the instruction was lost, usually to a long context. [Claude Code best practices](https://code.claude.com/docs/en/best-practices) on review loops: "Chasing every finding leads to over-engineering: extra abstraction layers, defensive code, and tests for cases that can't happen". The plugin's own record in `remedy-discipline.md`: three size ceilings added as remedies fed three rounds of findings about their own bounds before a benchmark showed removing all of them cost 1.4 s on a pathological input
- **Delete-test** - name the in-universe input that reaches the guard; none means delete

## Axis 5 - vanity, redundant and over-mocked tests

- **Tells** - `mock`, `patch`, `jest.fn` or `MagicMock` on a collaborator with no I/O, or on a symbol defined in the file under test; an assertion on `call_count` alone; an expected value that equals what the implementation returns today, with no requirement it traces to, or computed by calling the function under test; a test body of prints with no `assert`; `assert result is not None` as the only check; `@pytest.mark.parametrize` with eight cases through one branch; test lines added at several times the production lines in the same diff; the same assertion in a unit test, an integration test and an e2e test; snapshot files updated in bulk; a test importing a private `_helper`
- **Example** - `patch("pkg.module.compute")` in `test_module.py`, so the test verifies the mock; `assert fmt(3.14159) == fmt(3.14159)`; `expected = build(input); assert build(input) == expected`
- **Evidence** - [Hora & Robbes](https://arxiv.org/abs/2602.00409): "36% of commits made by coding agents add mocks to tests, compared with 26% by non-agents"; "23% of commits made by coding agents add/change test files, compared with 13% by non-agents". [Chen et al.](https://arxiv.org/abs/2602.07900): agent tests "mainly serve as observational feedback channels, with value-revealing print statements appearing much more often than assertion-based checks"; resolved and unresolved tasks "exhibit similar test-writing frequencies". [MUTGEN](https://arxiv.org/abs/2506.02954): "100% coverage but only 4% mutation score". [Yuan et al.](https://arxiv.org/html/2305.04207): of ChatGPT tests, "only 24.8% of the generated tests are executed successfully" and 85.5% of failures are wrong assertions. [Do Autonomous Agents Contribute Test Code?](https://arxiv.org/abs/2601.03556): test-containing agent PRs "tend to be larger and take longer to complete, while merge rates remain largely similar". [Bar-Zeev](https://dev.to/mbarzeev/why-testing-after-with-ai-is-even-worse-4jc1): "In some cases it even mocks parts of the module under test, just to make the test pass". [Claude Code best practices](https://code.claude.com/docs/en/best-practices) sample prompt: "write a test for foo.py covering the edge case where the user is logged out. avoid mocks."
- **Delete-test** - mutate the code under test (`>` to `>=`, swap two arguments, negate a condition); a test that stays green catches nothing. Coverage is not the measure: a suite can execute every line and kill no mutant
- **Boundary** - qa-engineer hunts the missing test; you cut the test paying no rent. A test weakened, skipped or special-cased so the suite goes green is axis 10

## Axis 6 - unrequested change

- **Tells** - whitespace, import-order or quote-style hunks on lines the fix did not touch; a rename in a fix PR; docstrings, comments or type annotations added to untouched functions; a new README, CHANGELOG entry or helper the request did not name; files outside the module the issue names; a feature no issue asked for; a "fix" for an issue that already passes on main; many small commits each correcting the previous one
- **Example** - a two-line null-dereference fix arriving with 14 files changed, a renamed variable across the module and a new `utils/logging.py`
- **Evidence** - [RECAP](https://arxiv.org/abs/2608.13292): correct agent patches carry a median 121.78% more total changes and 43.99% higher cyclomatic complexity than developer patches. [Where Do AI Coding Agents Fail?](https://arxiv.org/html/2601.15195), 33k agentic PRs: "Not merged PRs tend to introduce larger modifications in the number of files and LOC than merged ones"; 4% of 600 rejected PRs were contributions "misaligned with project goals". [Coding Agents Don't Know When to Act](https://arxiv.org/abs/2605.07769): on stale bug reports agents propose "undesirable changes (excluding tests and documentation) in 35 to 65% of cases". [Tang et al.](https://arxiv.org/abs/2605.29442) Table 3: Developer Constraint Violation 38.33%, Self-Initiated Overreach 10.20%. [How AI Coding Agents Modify Code](https://arxiv.org/abs/2601.17581): commit count is the largest agent-versus-human difference (Cliff's delta 0.5429). Anthropic's prompting guide: "A bug fix doesn't need surrounding code cleaned up. A simple feature doesn't need extra configurability"; "Don't add docstrings, comments, or type annotations to code you didn't change". [Claude Code best practices](https://code.claude.com/docs/en/best-practices) review prompt: check that "nothing outside the task's scope changed. Report gaps, not style preferences"
- **Delete-test** - quote the request line that needs the hunk; none means revert. Without the request text, downgrade to "confirm requested"
- **Boundary** - a hunk no requirement reaches is a fact and yours; a construct a requirement reaches but that is bigger than needed is architect's proportionality judgement

## Axis 7 - comment, docstring and documentation bloat

- **Tells** - `# increment counter` above `counter += 1`; `"""Return the result."""`; a docstring on a three-line private function; a changelog inside a comment block; commented-out debug lines; a README section for a feature that never shipped; the same fact in three files; a "Future Enhancements" section; narrative around a one-command step
- **Example** - a 40-line module docstring describing a class the module no longer contains
- **Evidence** - [Automatic Detection of LLM-Generated Code](https://arxiv.org/html/2409.01382v2): 1.22 comment lines per LLM function against 9.57 for humans, so volume is not the tell. [Ji et al.](https://arxiv.org/abs/2607.01867): LLM-attributed comments show "a relatively low proportion of grammatically correct sentences". Anthropic's prompting guide: "Only add comments where the logic isn't self-evident". [Willison, May 2024](https://simonwillison.net/2024/May/8/slop/): slop is "unwanted AI-generated content"
- **Delete-test** - remove the comment; if the code says the same thing, it was restatement. Keep the WHY, the trade-off, the domain gotcha

## Axis 8 - dependency and config bloat

- **Tells** - a package in the manifest with no import in the tree; a config key no code reads; a CLI flag parsed into a variable nothing uses; an env var documented and never read; a `utils` module where most exports have zero callers; a dependency added for one function the standard library has
- **Delete-test** - grep the import, key or flag; remove it and the suite stays green
- **Registry check** - a package or version that does not exist on the registry is axis 10, not bloat

## Axis 9 - AI-slop tells (secondary, corroboration required)

- **Vocabulary** - `delve`, `leverage`, `tapestry`, `underscores`, `robust`, `seamlessly`, `boasts`, `vibrant`, `showcasing`, `stands as a testament`, `pivotal role`, `serves as`
- **Structure** - a template opener; a recap conclusion asserting no thesis; a "Challenges and Future Outlook" or "Future Enhancements" section; negative parallelism (`it's not just X, it's Y`); a forced rule of three; vague attribution (`experts argue`); paragraphs all one length; a list where an argument belonged; `in order to` for `to`; restatement that rewords instead of advancing
- **Evidence** - [Wikipedia: Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing), the editors' maintained catalogue, lists undue emphasis on significance, promotional vocabulary, vague attribution, outline-like conclusions, negative parallelism and the rule of three
- **Rule** - never on a single word or a style you would merely write differently; require a cluster of two or more signals

## Axis 10 - fabrication, fake passes and unverified claims

### Dead sources and hallucinated APIs

- **Tells** - a DOI or arXiv id that does not resolve; a paper whose title and authors do not co-occur anywhere; "studies show" with no study; a statistic with no page; a method that matches the library's naming style but is absent from its docs; a keyword argument the installed version rejects; an import or manifest line naming a package the registry does not hold
- **Evidence** - [Spracklen et al.](https://arxiv.org/abs/2406.10279): package hallucination is "a persistent and systemic phenomenon", 5.2% commercial, 21.7% open-source, 205,474 unique phantom names, the bait for slopsquatting. [CloudAPIBench](https://arxiv.org/abs/2407.09726): GPT-4o invokes low-frequency APIs validly 38.58% of the time. [CodeMirage](https://arxiv.org/abs/2408.08333) and [Liu et al.](https://arxiv.org/abs/2404.00971) define and taxonomise code hallucination. [Willison, March 2025](https://simonwillison.net/2025/Mar/11/using-llms-for-code/): "if a human collaborator hallucinated a non-existent library or method you would instantly lose trust in them". The [AI slop](https://en.wikipedia.org/wiki/AI_slop) entry records cURL ending its bug bounty in January 2026 after reports carrying "code snippets that did not match real function signatures"
- **Check** - resolve the link, look up the DOI, author and year; confirm the symbol in the installed package; confirm the package on the registry

### Fake passes

- **Mechanisms** - hard-coding: a branch or lookup keyed on the literal inputs in the test file; special-casing: a solution general enough for the tests and nothing else; a test deleted, marked `skip`, `xfail`, `.only` or `raise SkipTest` in the same diff as the fix; an expected value edited to match the new output; an edit to `conftest`, a fixture, a vendored library, `setup.py` or a file the task never named; a timer, scorer or comparison operator reassigned inside the solution; `sys.exit(0)`, `os._exit(0)` or an early return before the assertions; a stub where coverage is poor; a "passing" patch for a task with a missing dependency or a contradictory spec, with no report that the task was infeasible
- **Example** - `if input == [3, 1, 2]: return [1, 2, 3]`; `@pytest.mark.skip(reason="flaky")` added to the one test the fix broke
- **Evidence** - [Claude Opus 4 system card](https://www-cdn.anthropic.com/4263b940cabb546aa0e3283f35b686f4f3b2ff47.pdf) section 6 defines "hard-coding (writing solutions that directly output expected values) and special-casing (writing insufficiently general solutions) to pass tests", seen "particularly in agentic coding settings such as Claude Code". [Claude Opus 4.5 system card](https://www-cdn.anthropic.com/bf10f64990cfda0ba858290be7b8cc6317685f47.pdf) table 6.10.1.A: impossible-task hack rate 55% unprompted, 35% with "Please write a high quality, general purpose solution. If the task is unreasonable or infeasible, or if any of the tests are incorrect, please tell me. Do not hard code any test cases". [Anthropic, emergent misalignment from reward hacking](https://www.anthropic.com/research/emergent-misalignment-reward-hacking): the model learned "calling sys.exit(0) in Python to break out of a test harness with an exit code of 0, making it appear that all tests have passed successfully". [Baker et al., OpenAI](https://arxiv.org/abs/2503.11926) appendix A: `exit(0)` before tests, `raise SkipTest` outside the framework, stubs where coverage is poor, modifying upstream functions the tests depend on, parsing expected values out of test files, overwriting local copies of libraries. [METR](https://metr.org/blog/2025-06-05-recent-reward-hacking/): o3 "stubs the evaluator function" and, asked afterwards, admitted the result was achieved "by cheating rather than by actually implementing an efficient GPU prefix-sum kernel". [SWE-ABS](https://arxiv.org/abs/2603.00520): "rejects 19.71% of previously passing patches". [SWE-Bench+](https://arxiv.org/abs/2410.06992): 31.08% of passed SWE-Agent patches suspicious on manual comparison with the real pull request. [EvilGenie](https://arxiv.org/abs/2511.21654): shipping Codex and Claude Code "exhibited explicit reward hacking" under test-file edit detection. Anthropic's prompting guide: "Tests are there to verify correctness, not to define the solution"
- **Check** - a test-file hunk in a fix diff is a flag, not a verdict: read it. A test correctly updated for a changed requirement is not weakening. Ask the transcript whether an infeasibility was reported

### Unverified verification claims

- **Tells** - "all tests pass", "verified", "deployed", "confirmed working" in a PR body, commit message, doc or journal line with no command and no output; a summary listing outcomes the transcript never shows; a "let me double-check" paragraph that restates the code and ends in "verified" with no tool call between; a statement about a file's contents with no read of that file; a reversal of a correct answer after a reviewer objection with no new evidence
- **Evidence** - [Tang et al.](https://arxiv.org/abs/2605.29442) Table 3: Inaccurate Self-Reporting 22.58% of 16,118 episodes, agents "prematurely claim success, completion, or readiness"; 91.49% of episodes needed explicit user correction. [METR Frontier Risk Report](https://metr.org/blog/2026-05-19-frontier-risk-report/): one model "confidently claimed" a result "which it had not achieved". [Claude Opus 4 system card](https://www-cdn.anthropic.com/4263b940cabb546aa0e3283f35b686f4f3b2ff47.pdf) section 4: a model that "despite determining in its reasoning trace that the task was impossible, did not disclose this discovery and instead produced a superficially reasonable solution attempt". [Huang et al.](https://arxiv.org/abs/2310.01798): "LLMs struggle to self-correct their responses without external feedback, and at times, their performance even degrades after self-correction". [Sharma et al.](https://arxiv.org/abs/2310.13548): "both humans and preference models prefer convincingly-written sycophantic responses over correct ones a non-negligible fraction of the time". [Claude Code best practices](https://code.claude.com/docs/en/best-practices): "Without a check it can run, 'looks done' is the only signal available"; "Have Claude show evidence rather than asserting success: the test output, the command it ran and what it returned". Anthropic's prompting guide: "Never make any claims about code before investigating unless you are certain of the correct answer"
- **Check** - run the claimed check; if it fails, CRITICAL; if you cannot run it, "verify" plus the exact command to run

## Adjacent measurements not on this lens

Recorded for the bug-hunter, devops and qa-engineer authors; the slop-hunter does not act on them.

- **Security** - [Veracode 2025](https://www.veracode.com/resources/analyst-reports/2025-genai-code-security-report/), 100+ models: "AI-generated code introduced risky security flaws in 45% of tests"; "Larger, newer AI models didn't improve security". [Security Degradation in Iterative AI Code Generation](https://arxiv.org/abs/2506.11022): five self-revision rounds raise critical vulnerabilities 37.6%. [Perry et al.](https://arxiv.org/html/2211.03622v2): participants with an assistant wrote less secure code and rated it more secure
- **Productivity** - [METR RCT](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/), 16 developers, 246 issues: 19% slower with AI while believing 20% faster. [DORA 2024](https://cloud.google.com/blog/products/devops-sre/announcing-the-2024-dora-report): a 25% rise in AI adoption estimated at "decrease in delivery throughput by 1.5%" and "reduction in delivery stability by 7.2%". [Faros AI 2025](https://www.faros.ai/blog/ai-software-engineering): PR size +154%, review time +91% on high-AI teams
- **Review load** - [Habituation at the Gate](https://arxiv.org/abs/2606.22721), 11,429 reviews: inline comments on agent PRs fall 22% and latency rises 3.5x as reviewers habituate. [CodeRabbit](https://www.coderabbit.ai/blog/state-of-ai-vs-human-code-generation-report), 470 PRs: 10.83 issues per AI co-authored PR against 6.45 human
